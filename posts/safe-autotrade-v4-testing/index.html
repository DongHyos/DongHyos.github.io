초록불을 믿지 않는다 — 샌드박스 없는 금융 API를 결정론으로 검증하기

이 글은
  • 다루는 문제: 실제 돈이 오가는 주문 API에 샌드박스가 없다. 실거래 테스트는 위험하고, 전부 mock으로 가리면 진짜 동작을 검증하지 못한다
  • 접근: 결정론적인 것(DB, 파일, 게이트웨이, 엔진)은 실물로 두고, 비결정적인 경계(네트워크·LLM)만 가짜로 좁힌다. 그리고 통과를 믿지 않고 결함을 일부러 심어 역검증한다
  • 결과·학습: 가짜는 두 경계(네트워크·LLM)뿐, 나머지는 실물. 447개 테스트가 네트워크·LLM 없이 결정론으로 돌고, 핵심 이음매는 결함 주입으로 통과가 진짜임을 확인한다. 실연동 미검증은 정직하게 범위 밖으로 둔다
  • 도움 되는 독자: 외부 API에 의존하는데 안전한 테스트 환경이 없는 개발자

돈이 오가는데 샌드박스가 없다

3편에서 토스 오픈 API에 샌드박스가 없다는 제약을 이야기했다. 이 글은 그 제약을 테스트 관점에서 정면으로 다룬다. 주문을 내는 코드를 어떻게 시험하나. 실거래로 시험하면 진짜 돈이 나가고, 그렇다고 전부 가짜로 감싸면 정작 검증하려던 동작이 사라진다.

두 번째 함정이 덜 알려져 있지만 더 위험하다. 게이트웨이도 가짜, 저장소도 가짜, 응답도 미리 정한 값으로 가짜로 만들면 테스트는 항상 초록불이 된다. 그런데 그 초록불은 내가 짠 가짜들끼리 말이 맞는다는 뜻일 뿐, 진짜 배관이 동작한다는 증거가 아니다. 정규화가 깨져도, 상태 전이가 틀려도 테스트는 통과한다. 가짜가 그 결함을 덮어버리기 때문이다. 나는 이걸 mock 안티패턴이라 부른다. 샌드박스가 없다는 이유로 전부를 가짜로 만들면, 테스트는 통과하는데 시스템은 틀리는 최악에 빠진다.

그래서 질문을 바꿨다. "무엇을 가짜로 만들까"가 아니라 "무엇만 가짜로 만들어도 되나"로.

접근: 결정론은 실물로, 비결정만 가짜로

기준은 단순하다. 결정론적인 것은 실물로 쓰고, 비결정적인 것만 가짜로 좁힌다.

내 시스템에서 결정론적인 부분은 대부분이다. SQLite 저장소는 같은 입력에 같은 결과를 주고, 파일 연산도, 케이지의 판단도, 엔진의 규칙 평가도 재현 가능하다. 이런 것들은 가짜로 바꿀 이유가 없다. 바꾸는 순간 검증 대상이 사라지니까. 비결정적인 것은 딱 둘이다. 외부 토스 API를 부르는 네트워크, 그리고 (뒤 레이어의) LLM 추론. 이 둘만 결과가 매번 다르고 통제할 수 없다.

그래서 테스트에서 실물로 두는 것과 가짜로 두는 것의 경계가 이렇게 갈린다.

구현: 주문 파이프라인의 가짜는 네트워크 하나

주문 파이프라인을 예로 들자. 여기 관여하는 비결정 경계는 네트워크뿐이다. LLM은 주문 판단에 끼어들지 않으므로(1편), 이 테스트에서 실제로 가짜가 되는 건 네트워크 하나다. 그 네트워크를 대체하는 FakeTransport는 스크립트된 토스 응답을 순서대로 돌려준다. 핵심은 두 가지다. 예외도 큐에 넣어 타임아웃이나 429를 재현할 수 있고, 게이트웨이가 실제로 만든 요청을 기록해 "무엇을 어떤 형태로 보냈나"를 검증할 수 있다.

class FakeTransport:
    """토스 경계만 대체하는 가짜 transport. 네트워크는 0."""
    def __init__(self, responses):
        self.responses = list(responses)  # 스크립트된 토스 응답/예외 큐
        self.requests = []                # 게이트웨이가 '실제로' 만든 요청 기록

    def send(self, request):
        self.requests.append(request)     # 무엇을 보냈나 — JSON 형태 교차 검증용
        nxt = self.responses.pop(0)
        if isinstance(nxt, Exception):
            raise nxt                     # 타임아웃·429도 큐로 재현
        return nxt

이 네트워크 하나를 뺀 나머지는 전부 실물로 배선한다. 케이지도, 그 아래 게이트웨이도, 설정, 상태, 감사 저장소도 진짜다. 상태와 감사는 임시 경로의 실제 SQLite를 쓴다.

def _wire(state, audit, secret_store, transport):
    # 게이트웨이는 실물 — 오직 그 아래 네트워크(transport)만 가짜다.
    gateway = BrokerGateway(transport=transport, secret_store=secret_store,
                            sleep=_SpySleep(), max_retries=2)  # sleep도 주입(429 결정론)
    cage = SafetyCage(
        settings=SettingsStore(_limits()),  # 실물
        state=state,                        # 실물 SQLite (tmp)
        audit=audit,                        # 실물 SQLite (tmp)
        gateway=gateway,                    # 실물 게이트웨이
    )
    return cage, gateway, transport

여기엔 중요한 세부가 하나 더 있다. FakeTransport가 돌려주는 응답은 가짜 단순형이 아니라 토스가 실제로 주는 형태 그대로다. 시세는 {"result": [...]} 안에 lastPrice로, 캔들은 closePrice로 중첩돼 들어온다. 왜냐하면 그래야 게이트웨이의 정규화 코드(3편에서 다룬 closePrice→close 변환)가 테스트 경로에서 실제로 실행되기 때문이다. 응답을 미리 깔끔하게 정리해 넣으면 정규화가 건너뛰어지고, 그 배관은 검증되지 않은 채 남는다. sleep도 주입해 실제로 기다리지 않으면서 429 재시도를 결정론으로 검증한다. 그 결과 447개 테스트 전체가 네트워크와 LLM 호출 0으로, 매번 같은 결과로 돈다.

통과를 믿지 않는다: 결함을 일부러 심는다

실물을 최대한 쓰면 초록불의 신뢰도가 올라간다. 하지만 그것만으로는 부족하다. 테스트가 통과한다는 것이 정말 그 불변을 강제하고 있다는 뜻인지는 별개의 문제이기 때문이다. 아무것도 단언하지 않는 테스트도 통과한다.

그래서 핵심 안전 이음매마다 결함을 일부러 심어봤다. 프로덕션 코드를 잠깐 망가뜨리고, 그것을 지키는 테스트가 실제로 빨간불이 되는지 확인한 뒤 즉시 되돌리는 것이다. 빨간불이 되지 않으면 그 테스트는 아무것도 지키지 못하고 있었다는 뜻이다.

일부러 심은 결함 기대 결과
모드 게이트 무력화(SHADOW에서도 집행) SHADOW 실주문 0 테스트가 깨짐 ✅ 깨짐 → 되돌림
정규화 키 오변경(closePrice를 못 읽게) 지표 미산출 → 무발주 → E2E 깨짐 ✅ 깨짐 → 되돌림
주문 전송 예외를 밖으로 누수 타임아웃 복구 테스트가 깨짐 ✅ 깨짐 → 되돌림
멱등 가드를 한 겹만 무력화 (중복 주문 발생?) ❌ 안 깨짐 — 다른 세 겹이 막음

마지막 줄이 흥미로웠다. 멱등을 한 겹만 부러뜨렸을 때는 테스트가 여전히 통과했다. 2편에서 다룬 네 겹 방어가 서로를 받쳐주기 때문이다. 네 겹을 동시에 무력화해야 비로소 중복 주문이 뚫리고 테스트가 깨졌다. 이건 테스트가 부실하다는 신호가 아니라, 프로덕션 방어가 두텁다는 신호였다. 결함 주입은 이렇게 테스트의 진위뿐 아니라 방어의 깊이까지 드러낸다.

결과와 정직한 한계

이 전략의 결과는 이렇다. 447개 테스트가 네트워크·LLM 없이 결정론으로 돌고, 실물 저장소와 게이트웨이를 그대로 통과하며, 핵심 이음매는 결함 주입으로 통과가 헛것이 아님을 확인했다.

그러나 정직해야 한다. FakeTransport는 토스가 주는 응답의 형태를 모사할 뿐, 실제 토스 서버가 아니다. 그래서 검증되지 않는 것이 분명히 있다. 토스 API 스펙이 GA 과정에서 바뀌면 내 모사와 어긋날 수 있고, 실제 rate limit 수치나 체결·부분체결의 타이밍은 모사값일 뿐 실측이 아니다. 이런 것들은 실제 서버에 붙여야만 검증되는 영역이고, 나는 그것을 테스트가 커버하는 척하지 않는다. 실연동 계약 테스트는 실거래 단계의 몫으로 명시해 남겨둔다. 무엇을 검증했고 무엇을 안 했는지의 경계를 흐리는 것이야말로 테스트가 주는 가장 위험한 거짓 안심이다.

학습

첫째, 샌드박스가 없어도 결정론과 비결정의 경계를 그으면 대부분 테스트할 수 있다. 테스트할 수 없다고 느껴지는 시스템의 상당 부분은 사실 결정론적이다. 진짜로 통제 불가능한 것(네트워크, 외부 추론)만 골라내면, 나머지는 실물 그대로 검증 대상이 된다. "테스트 환경이 없다"는 흔히 "경계를 아직 안 그었다"는 뜻이다.

둘째, 전부 가짜로 만든 초록불은 거짓 안심이다. 가짜는 검증 대상을 덮는다. 실물 leaf를 쓰고 비결정 경계만 좁혀야, 정규화나 상태 전이 같은 진짜 배관이 테스트 경로에서 실행된다. 가짜로 응답을 깔끔하게 정리해 넣는 순간, 검증하려던 그 변환이 조용히 건너뛰어진다.

셋째, 통과하는 테스트는 결함을 심어 되물어야 진짜다. 초록불은 "코드가 맞다"가 아니라 "테스트가 반박하지 못했다"는 뜻이다. 결함을 일부러 심어 빨간불을 확인하면, 그 테스트가 정말 무언가를 지키고 있음을 안다. 이 되물음 없이는, 통과가 무엇을 보장하는지 스스로도 모르는 채로 초록불만 쌓게 된다.
